## 現行手順（0.7.0+）

現行のデスクトップアプリケーション（0.7.0）は、以下の旧 0.1.x 版エディタと比べて
機能が大きく拡張されています: POI エディタ、5種類の資源一覧
（地図/アプリ/POI/ベースマップ/アセット。全文検索は5種類全て、範囲（bbox）検索は
うち4種類（地図・POI・ベースマップ・アプリ）で利用可能）、自動保存される下書き、
アプリ単位のエクスポート/インポートなど。本節では現行の操作手順を説明し、
ステップバイステップのレガシーチュートリアルは歴史的参考としてこの下に残しています。

### 1. 地図の作成と対応点（GCP）設定

MaplatEditor は起動すると **地図管理** 画面が開き、保存済みの全地図に加えて、
新規作成用の **新規作成** ボタンと、以前エクスポートした地図（`.zip`）を取り込む
**インポート** ボタンが表示されます。作成したがまだ保存していない地図は、
ディスクへ書き込まれる代わりにオレンジ色の **Draft**（下書き）カードとして
この一覧に表示されます。詳細は下記[「4. 下書きと保存」](#4-下書きと保存)を参照してください。

地図・アプリ・POI ソースの各一覧では、保存済み行に診断バッジが表示されることがあります。
黄色の warning バッジは、POI ソース参照欠損、アセット実体欠損、ベースマップサムネイル欠損、
またはアプリの旧形式 `pois` が未対応形式であることなど、preview/export 時に警告または
出力欠落につながる状態を示します。赤い danger バッジは、コンパイル済み地図が
`strict_error` である場合や、アプリが欠損地図または `strict_error` 地図を参照している場合の
ように、より強いゲート拒否状態を示します。アプリ側の danger 状態は、保存・preview・
エクスポートをブロックする条件と同じです。一方で、地図自身のパッケージエクスポートは
壊れた地図データを修復用に持ち出せるよう引き続き実行できます。

![地図一覧。保存済み地図2件と未保存の下書きカード1件](images/current-1-map-list.png)

地図（新規・既存いずれも）を開くと **対応点編集** タブが表示され、左に絵地図、
右に正確な現代地図が並びます。対応点（GCP）とは、絵地図を実世界の座標へ変形する
ために Maplat が使う「対応する地点」のペアです。下記スクリーンショットの番号付き
マーカーと接続線は、4組の対応点を示しています。右側の現代地図には、
ジオコーダーによる住所検索支援と、既に置いた GCP から地図のホームポジション・
ズームレベルをワンクリックで推定するボタンが用意されています。対応線を
**右クリック** すると、その中間点に新しい GCP を挿入して線を分割できます
（旧エディタから引き継いだ操作方法です）。

![地図編集の対応点編集タブ。絵地図と現代地図の両方に GCP マーカーが表示され、ヘッダーに Export ボタンも見える](images/current-2-map-edit-gcp.png)

*現代地図タイル: © [OpenStreetMap](https://www.openstreetmap.org/copyright) contributors.*

### 2. POI の追加と編集

POI エディタでは、地図上で直接 POI（Point of Interest）の追加・移動・削除ができ、
各 POI の多言語名称・説明・HTML・住所・URL・アイコンを編集できます。POI ごとに
**Standard**・**HTML**・**Web Page** の3種類のコンテンツモードが選択でき、
共有の Assets ピッカーからアップロードしたアセットを参照するインライン画像参照も
利用できます。**Raw** トグルで下層の GeoJSON を直接編集することもでき、すべての
編集は Undo/Redo（Cmd/Ctrl+Z、Shift+Cmd/Ctrl+Z または Y）に対応しています。

![POI エディタ。地図、コンテンツモードタブ（Standard / HTML / Web Page）、フィーチャー一覧を表示](images/current-3-poi-editor.png)

*背景地図タイル: © [OpenStreetMap](https://www.openstreetmap.org/copyright) contributors.*

古い地図・アプリのデータには、POI が地図・アプリのドキュメント内に直接埋め込まれて
いる場合があります（旧形式の inline `pois` 要素）。これらはそのまま保全されます:
POI データタブではビューアのレイヤ単位のペインにまとめられ、項目数と2種のバッジ
（「**地図内定義POI**」/「**外部URL参照**」）つきで読み取り専用表示され、
保存・エクスポートでも無変更で透過されます。編集したい場合は、レイヤ単位の明示操作
「**GeoJSONへ変換**」を使ってください（変換ボタンは1レイヤに1個 — 単層の配列は全体を
1回で、複層の一覧は FeatureCollection カードごとに1回で変換） — 元データを変更せずに、
自動採番された slug で新しい POI ソースの下書きが作成されます。下書きは POI 一覧から
編集・保存でき、地図・アプリ側を新しい POI ソース参照へ切り替えたら、元の埋め込み
要素を（確認ダイアログつきで）削除できます。なお、埋め込みデータが一覧に残っている
間は、ビューアが2つの形式を1つの一覧内で混在させられないため、GeoJSON POI ソースを
並べて追加することはできません。

### 3. アプリの作成

アプリエディタでは、ベースマップ・1件以上の登録地図（ソース）・POI ソースを
組み合わせ、カバレッジ範囲の描画や PWA/OGP メタデータ（アイコン・スプラッシュ
画像・キーワード・正規URL）の設定を行います。**Preview** タブでは、他のタブで
選択したソースと POI を使って、エンドユーザーが実際に見る状態のアプリを
プレビューできます。

![アプリエディタのプレビュータブ。選択したベースマップと POI マーカーを表示](images/current-4-app-editor-preview.png)

### 4. 下書きと保存

編集内容は数秒ごとにローカル下書きとして自動保存され、リソースを閉じて
再度開いたときに復元されます。地図・アプリ・POI・ベースマップ・アセットは
いずれも同じ「保存するまで作成されない」という挙動に統一されています:
放棄された新規リソースの下書きはディスクへは一切書き込まれず、代わりに
資源一覧の中に下書きカードとして表示され（上記の[地図一覧のスクリーンショット](#1-地図の作成と対応点gcp設定)
参照）、そこから再開または破棄できます。地図を削除すると、即座に消去される
のではなくゴミ箱の場所へ移動します。

### 5. エクスポートとインポート

- 地図は、地図エディタのヘッダーにある **Export** ボタンでエクスポートします
  （上記の[対応点編集タブのスクリーンショット](#1-地図の作成と対応点gcp設定)に
  写っています）。このボタンはどのエディタタブを開いていても常に利用できます。
  以前エクスポートしたファイルから新規地図をインポートするには、**地図管理**
  一覧の **インポート** ボタンを使います（上記の[地図一覧のスクリーンショット](#1-地図の作成と対応点gcp設定)
  に写っています）。
- POI ソースは GeoJSON 形式でエクスポートされ、画像参照を含む場合は ZIP
  パッケージとしてエクスポートされます。インポート時は内部の画像参照が
  自動的に解決されます。アプリは単一の ZIP（`{appID}.zip`）としてエクスポート
  され、静的な PWA 対応ビルド（マニフェスト・アイコン・スプラッシュ画像）を
  含めることもできます。いずれも各エディタのヘッダーにある同じ **Export**
  ボタンのパターンを使います（上記の[POI エディタ](#2-poi-の追加と編集)・
  [アプリエディタ](#3-アプリの作成)のスクリーンショットに写っています）。
- 対応点（GCP）エラーが未解決の地図はプレビューできませんが、地図自体の
  エクスポートは成功します。そのような地図を含むアプリ、またはデータベースに
  存在しない地図（削除済みなど）を参照するアプリは、問題が解決されるまで
  保存・プレビュー・エクスポートがブロックされます。同じアプリブロック状態は、
  アプリ一覧の赤いバッジとして先に表示されます。黄色の一覧バッジはそれ自体では
  保存ゲートをブロックしませんが、preview/export が警告する参照やアセットの欠落を
  示します。（README の
  [エクスポートとインポート](../blob/master/README.ja.md#エクスポートとインポート) 節からの
  引用です — 最新かつ完全な文言はそちらを参照してください。）

## レガシーチュートリアル（0.1.x 時代・アーカイブ）

> 以下は旧 Wiki 内容（0.1.x 時代・2018年頃）を歴史的参考として保持しているものです。
> より単純な旧エディタ（単一の地図一覧 + GCP設定タブ）を前提としており、POI
> エディタ・master-detail 資源一覧・下書き・エクスポート/インポートなど、
> それ以降に追加された機能には触れていません。現行の操作手順は上記の
> [現行手順](#現行手順070)節を、現行の開発セットアップは

### 1. 新しい地図を作成する

MaplatEditor を起動すると地図一覧が表示されます。**新規作成** ボタンを
クリックして新しい地図を作成します。

![新規作成](images/howtouse1createnew.png)

メタデータフォームへ入力します。必須項目は3か所:

- **地図 ID** — ファイル名になります。半角英数字のみ使用可。
  **一意性確認** ボタンで重複がないか確認してください。
- **地図名称** — 人間が読む地図の名前。
- **地図画像コピーライト** — ビューアに表示される著作権表示文字列。

![必須メタデータ](images/howtouse3mandatorymeta.png)

必須項目を入力すると **保存** ボタンが押せるようになります。保存後、
次回起動時の地図一覧に表示され、編集を再開できます。

![保存ボタン](images/howtouse4savebutton.png)

### 2. 地図画像をアップロードする

編集画面の **地図アップロード** ボタンを押します。

![アップロードボタン](images/howtouse5uploadbutton.png)

ファイル選択ダイアログで JPEG 画像を選択します（旧 UI では `.jpg` のみ
対応。現行の対応形式は README を参照してください）。

![アップロード選択](images/howtouse6uploadselect.png)

アップロードが完了するまで少し（画像サイズによっては相当）時間が
かかります。完了メッセージが出たら、**対応点設定** タブが選択できるように
なります。

![アップロード完了](images/howtouse7uploadfinish.png)

### 3. 対応点（GCP）を設定する

対応点設定タブを開くと、左に絵地図、右に正確な地図が表示されます。

![マッピング開始](images/howtouse8mappingstart.png)

右の地図の虫眼鏡ボタンが地名検索窓です。地名を入力すると地域を絞れます。

![地名検索](images/howtouse9placesearch.png)

右の地図の右上ボタンでベースマップを切り替えられます
（OpenStreetMap / 地理院地図 / 古い航空写真 / 今昔マップ on Web 等）。
現代では失われている道路・河川・地形などを元にマッピングしたい場合は、
国土地理院の古い航空写真や今昔マップ on Web の地図を使うと有用です。

![ベースマップ選択](images/howtouse10basemapselect.png)

対応点を置きたい場所で **右クリック** し、**マーカー追加** を選ぶと
その場所に対応点マーカーが置かれます。左右の地図はどちらから先にマーカーを
置いてもいいですが、交互に置く必要があります（1組で1つの GCP になります）。

![マーカー配置](images/howtouse11addmarker.png)

### 4. マーカーの編集と削除

- **移動** — 左クリックでドラッグすると自由に動かせます。
- **削除** — マーカー上で右クリックし **マーカー削除** を選ぶと、
  左右両方の対応点が一度に削除されます。
- **対応点表示** — 右クリックし **対応マーカー表示** を選ぶと、
  対になるもう一方の地図のマーカーを探して表示します。
  マーカーだらけになって探しづらい時に便利です。

![対応点表示・削除](images/howtouse13showpairs.png)

### 5. 保存

いつでも **保存** ボタンを押すと、対応点とメタデータが保存されます。

![マーカー保存](images/howtouse12addedmarkers.png)

### 開発環境セットアップ（レガシー）

> 以下は 0.1.x 時代の Electron + ImageMagick + submodule sparse-checkout
> フローです。現行の開発セットアップは Vite + pnpm ベースであり、
> [README § 開発](../blob/master/README.ja.md#開発) に記載されています。

レガシーセットアップでは以下が必要でした:

- Node.js + Electron
- ImageMagick（タイル生成が使用する `convert` コマンド用）
- submodule sparse-checkout 付きのリポジトリクローン（同梱 Maplat
  ソースをスリム化するため）

エンドユーザーにはこれらの手順は不要です。[README](../blob/master/README.ja.md)
からデスクトップインストーラーをダウンロードしてください。
